# BT 在线时长口径与验收

最后修改日期：2026-09-09

用户要求：统计后台用当前 LinkGame 优化版；在线时长包含广告，记录间隔从30秒改15秒。后台页面、筛选与 SQL 沿用原版；本次只增加口径提示。

- 正常前台：继续 Cocos 帧时间累计，单帧上限1秒；普通切后台停止计时，恢复首帧不补挂起时间。
- 广告：只对当前登录会话发起且收到实际 ad_show 的展示区间计时，直至 ad_close/ad_success/ad_fail。加载/请求不视作播放；提前关闭仍计实际展示区间。
- 广告时间与前台帧时间互斥，多个展示区间取并集；不能把两个时钟或后台 ad_duration_ms 再相加。
- 每15秒生成 online_time；关闭/隐藏时结算整数尾段，小数保留到下一段。定时器可运行时广告每15秒采样；TikTok 若挂起 JS，则回调恢复时补记15秒分段，无法保证挂起期间恰好每15秒发网络请求。
- 重复close/success/fail不会再累计；会话重置后旧回调不记入新账号。缺终止回调最多计30分钟，随后停止该异常广告计时。
- 定义是 SDK 展示区间，不是纯视频播放秒数。SDK 没有提供隐藏原因时，广告期间系统退到桌面的时间无法可靠从遮罩隐藏中区分；真机对照时需记录这一边界，不能声称已获得精确观看秒数。
- 平台进程被直接杀掉且无后续回调时，未获得的时间不能可靠补记；不伪造时间。已排队分段仍使用原持久化、批量重试和服务端事件 ID 幂等。

## 本地已验证

自动行为测试涵盖普通15秒、7秒尾段、31秒广告挂起分段、早关、播放失败、未展示失败、重复show/close/success、切号迟到回调、广告区间重叠、缺回调上限、小数帧累计；真实 GameAnalyticsService 计时器和队列也验证45秒广告生成3个15秒事件。

服务端维持1～300秒分段协议并验证15秒和短尾段。后台在线字段仍直接求和，未修改数据库 migrations。

## 新环境真机验收（待配置）

记录同一测试账号：前台30秒＋广告45秒＋普通后台20秒，期望在线约75秒（不含普通后台，允许帧采样/整数尾段造成的小误差）。核对原始 online_time 唯一ID和秒数之和、累计在线/人均在线显示。断网后重传不能翻倍。

分别验激励完播、早关、播放失败、无填充、插屏、广告遮罩 hide/show 顺序、长广告挂起、重复点击、关闭前退后台、切账号、杀进程。此部分不能用本地模拟代替。
