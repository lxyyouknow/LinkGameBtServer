1. 填 config/project.json 运维清单，填写新 .release.env 与远端独立 app.env。运行 `node scripts/bt-project.mjs generate` 生成公开发布设置、systemd/nginx、远端比对脚本与 app.env.example。实际 app.env 的秘密须单独填写。
2. 新库和新权限用户使用 linkgame_bt_ 前缀；配置 BT_PROJECT_KEY、BT_ENV、APP_ENV 和 BT_DB_*。staging/production 必须关测试登录，开 TikTok，并填新 Client Key/Secret。

4. 填完后执行 `node scripts/bt-project.mjs check --release`；发布入口已接好此预检。远端先执行 deploy/check-target.sh 比对环境，再运行 linkgame-bt-check-config 校验完整运行配置，两者通过才运行 migrate。不要跳过这些检查。
5. 经授权仅对新测试库执行原 migrations，启动并验健康、TikTok 换票、存档、奖励及统计；真机通过后准备正式环境。

应用当前有配置级防误连校验，尚无数据库 project_identity 表或远端实例身份握手。实际库权限与部署目标仍需运维核对。

## 首次部署补充（2026-09-09）

运维先建新库与权限用户、新服务器独立部署目录/shared/app.env，并配置用户级 systemd/lingering、TLS 反向代理和白名单。脚本不上传秘密、不自动安装 Nginx/TLS 或操作系统权限。后续有当前任务部署授权时可运行 `sh scripts/release-production.sh --yes`；Windows 使用对应 PowerShell 脚本。releaseEnabled=false 时不会访问服务器。

构建包包含 API、migrate、check-config 三个 Linux amd64 二进制与原 migrations。配置级检查不连接数据库；migration 才使用新库连接。回滚只切回旧程序，不会自动回退数据库 schema。
