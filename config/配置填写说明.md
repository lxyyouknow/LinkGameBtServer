最后修改日期：2026-09-09

当前状态：新环境尚未申请，所有云地址及平台 ID 均留空。游戏可在 Creator 本地预览；正式 TikTok 构建/发布被配置预检阻止。

## 收到运维信息后怎么填

| 信息 | 保存位置 | 说明 |
|---|---|---|
| 新 API HTTPS 地址 | ../LinkGameBt/config/environments/<环境>.json 的 apiBaseUrl | 与新服务端域名一致 |
| 新 CDN 项目根 URL | 同文件 cdnBaseUrl | 必须映射到下面同一 S3 前缀的内容 |
| S3 区域、桶、账号、profile | 同文件 aws | profile 仅是本机 AWS 凭据配置的名字，密钥不在这里 |
| S3 前缀 | 同文件 aws.prefix | 固定 pairpop-bt/staging/tiktok-assets/ 或 production 对应值；与 CDN 映射一起确认 |
| 新 TikTok AppID、Client Key、两类广告位 ID | 同文件 tiktok | 不能使用旧应用；Client Secret 只填服务端 |
| SSH 主机/用户/密钥路径、远端目录、端口/域名 | 服务端 config/project.json 与 .release.env | 公共清单 + 被忽略的本机发布设置 |
| 数据库 host/port/name/user | 服务端 config/project.json 与运行环境 BT_DB_* | 新库名和新用户须使用 linkgame_bt_ 前缀 |
| 数据库密码、完整 DSN、TikTok Secret、GM 登录配置 | 服务端忽略的 .env 或远端 app.env | 不进 Git/公开配置/客户端 |

服务器、数据库实例和 CDN 不必各买一台独占硬件，但必须是新游戏独立的服务进程/域名、库/权限用户、资源路径和访问权限。lxy 已计划向运维申请新的一套，按独立资源配置接入最直接。

建议运维一次返回：测试与正式两套 API 域名/SSH/部署根目录/端口，新 MySQL 库和最小权限用户，新桶或严格独立前缀/CDN 映射/TLS，允许上传该前缀的 AWS profile 对应权限，日志与备份位置。TikTok 应用信息另由平台后台提供。不要混用测试与正式数据库。

## 客户端同步

1. 先填 staging 文件，并将 config/project.json 的 activeEnvironment 改成 staging。
2. 运行 `node scripts/bt-project.mjs generate`，再运行 `node scripts/bt-project.mjs check`。
3. 核对生成的运行配置、TikTok public-config 和 build-config 都来自同一环境。
4. 完成域名白名单、CDN 映射和新 API 可用性检查后才将 releaseEnabled 设为 true，运行 `node scripts/bt-project.mjs check --release`。该检查是字段及一致性检查，不会实际访问云资源，也不代替真机验收。
5. 获得本次上传/部署授权后先出测试环境包验收，再准备正式环境。

首个 BT 客户端版本从 0.1.0 开始。analyticsAppId 保留 1，与原服务端接口一致，依赖独立数据库隔离。禁止为改项目名而修改关卡、奖励或广告位语义。按 2026-09-09 最新要求，online_time 改成每15秒并计入广告，后台仍直接对秒数求和。

服务端填 config/project.json 后运行 `node scripts/bt-project.mjs generate`，自动生成 .release.env（忽略）、systemd/nginx、deploy/check-target.sh 和 app.env.example；真实秘密不自动生成。3306/3318/24020 等模板端口只是本地或示例，正式以运维分配为准。配置检查通过并将 releaseEnabled 设为 true 后即可走现有发布入口，无需再改代码。

## 两端最后配对（2026-09-09）

服务端公开配置 environment 必须与客户端 activeEnvironment 一致；tiktokClientKey 与客户端 Client Key 一致；apiDomain 仅填主机名，不带 https:// 或路径。服务器的 HTTP_ADDR 由端口生成在 app.env.example 中。先填 staging，后续生产环境单独保存自己的 config/project.json 与秘密文件。

在服务端执行 generate、check、check --release；在客户端执行 generate、check --release、`node scripts/check-bt-pair.mjs`（非相邻目录可传服务端目录）。全部都是本地检查，不会上传。

首次部署仍需要运维准备独立空数据库/权限用户、服务器 Node 不需要（只运行 Go）、用户级 systemd 与 lingering、HTTPS 反代、shared/app.env。将生成的 app.env.example 复制到这个新环境并填 DSN、TikTok Client Secret、GM 账号配置；以后部署不覆盖已有秘密文件。客户端/本机构建需要 Node 和 Creator 3.8.8，服务端本机构建需要 Node 与 Go。
